Validation and Goodhart audit

The repository has strong tests for records and weak tests for their visual meaning. Some current checks are more serious than incomplete proxies: their inputs are constructed to make the desired result pass. Preserve genuine file/state protections; replace circular quality and geometry evidence.

An output can pass file integrity, continuity arithmetic and collision checks while failing as compelling sequential art. Owner feedback and actual continuous reading outrank an internal quality score. Conversely, a noisy or dense panel should not fail solely because a proxy dislikes a deliberate spectacle beat.

Evidence links: technical measurements and source excerpts, technical causal findings, owner reactions, complete mechanism genealogy. This report is a static audit of existing validations, not a claim that protected builds were executed or every historical validator rerun.

Four directly observed Goodhart mechanisms

  1. Scores become code defaults. integrate.py sets the baseline/raw/hybrid quality vectors. editorial.py raises selected hybrid categories uniformly. model.py then requires the selected premium route to outperform the baseline. This rewards filling in winning numbers; the code never needs to observe 52 distinct quality outcomes.
  2. Geometry adapts to lettering. Reservations grow to contain authored units, and protected zones are chosen from options that avoid them. The gate rewards convenient rectangles. It should instead force lettering to respect independently observed content.
  3. Coverage becomes an ordinal loop. Required scenario names rotate by panel index. A large establishing panel obtains a close-up tag. The gate rewards bookkeeping coverage instead of tested capability.
  4. Novel hashes substitute for narrative fit. The unique52 build genuinely contains distinct art. Twenty-four benchmark plates are still selected for new beats, and some source prompts expressly request the wrong people, body state or event timing. Exact duplicate removal is an improvement with a narrow boundary.

These findings do not prove deliberate deception. They show how autonomous completion incentives and self-authored acceptance data can produce confident PASS labels without the underlying evidence.

Controls that worked and should survive

The archive preserves failed candidates, exact prompts, hash-pinned source selection, cross-chapter ledgers and scoped repairs. Borrowed Down proved 295/299 unaffected panel hashes unchanged for different repairs; City relocated seven lettering defects without source regeneration. G07 preserved negative evidence about role binding, target edits and no-change controls. Those are actual bounded observations. They stop accidental overwrite and clarify what a correction touched.

A deterministic compositor's exterior-zero-change result should stay a mechanical success. It should never be promoted to native generator edit fidelity. Similarly, state arithmetic can remain a hard gate without pretending to be a drama score. The leaner stack preserves those distinctions.

Hard semantic failures include an unexplained extra principal actor, an absent required contact, an irreversible injury/weapon reset, an event shown out of order, illegible required speech, a wrong speaker tail, generated prose contaminating an art field, or an unresolved adult-only/rights-boundary violation. Reviews may mark a genuinely occluded/unseen fact indeterminate rather than invent certainty. The next-pilot specification owns exact thresholds and decision margins; this audit does not invent a second competing rubric.

Minimal new failure-injection coverage

The next pilot needs only a few high-value additions to existing mechanical tests:

  • Substitute P012's four-adult source into a declared two-adult beat and require independent source-binding adjudication to reject it. A JSON field alone cannot automate the image judgment.
  • Label an establishing shot hero_close_up; require an annotation/evidence link and reviewer decision, not mere tag presence.
  • Preserve a unique SVG wrapper while replacing its leaf with another panel's raster; the leaf duplicate/revision check must detect it.
  • Change rendered container width below the font threshold while keeping nominal viewport390; actual phone typography must fail.
  • Move a balloon across an independently fixed visible face/contact annotation; the collision checker must fail without moving the annotation.
  • Alter an XP delta, inventory carry or required local source file; keep the existing arithmetic/hash/link failures.

Do not add hundreds of tests that merely mirror every generated metadata field. One observed bad source mapping is more informative than another self-consistent 52-row score table. The acceptance stack should make valid pages easier to select and invalid page claims harder to write.
