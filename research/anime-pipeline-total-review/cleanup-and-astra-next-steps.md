# Cleanup, tooling and the next move

**Restart the sequence-production workflow, not the entire project.** Keep Ember provisionally, stop treating the existing imagery as something the new storyboard must accommodate, and build one small canonical production path. A new title or model alone will not fix wrong-beat selection and self-confirming acceptance.

## What cleanup means

| Action | Concrete scope | Why / gate |
|---|---|---|
| Freeze the archive | All existing worktrees, generated art, prompts, failed candidates and owner records remain intact. List them as historical in one active-project index. | They are rollback and comparison evidence. No deletion, branch removal or cache reclamation was performed in this audit. |
| Establish one active pilot | A future isolated workspace has one frozen scene, rubric, cast/prop/environment contract, exact copy and acceptance ledger. Link this review and the best legacy samples. | Stop treating every experimental branch as an active production system. |
| Retain a small core | Source IDs/hashes, nullable provenance, state/inventory arithmetic, preserved attempts, editable lettering, export and actual phone-reader checks. | Use the minimum needed by the pilot; no blanket rewrite of 603 legacy modules. |
| Retire misleading acceptance | Workflow quality presets, round-robin coverage tags, zones invented around text and automatic winner requirements do not authorize promotion. | A valid file is distinct from a correct event and a compelling page. Retain genuine structural tests. |
| Replace the creative handoffs | Approved storyboard → original cast/prop sheets → exact source production → independent source/beat review → deliberate repair → lettering → complete-reader review. | Reject the wrong cast, event, contact or aftermath before polishing it. |
| Defer mechanical consolidation | Extract/consolidate proven code only after the pilot identifies a recurring need. Keep one current manifest and reader entry point. | Avoid spending another cycle reorganizing an unproven production process. |
| Consider physical deletion later | Only after a verified archive/restore inventory identifies exact redundant paths and bytes, with explicit removal scope. | The current preservation brief protects all old trees and caches; broad cleanup wording is not permission to erase unique work. |

A proposed active workspace can be simple: `brief/`, `storyboard/`, `assets/`, `candidates/`, `lettering/`, `reader/` and `evidence/`, with one pipeline manifest linking them. Those are a future organization proposal, not newly created empty infrastructure. The archive remains where it is, so provenance links keep working.

## Where Astra fits

Local read-only verification found `gpt-6-astra` selected in the Codex configuration and listed in the local model cache. This confirms the configured option; it does not supply audited token billing, a backend snapshot or the identity of any image generator. We did not change the configuration or start a paid API workflow.

Official OpenAI documentation describes Astra as a model for demanding reasoning, coding, computer use, research and document work. Its native modalities are text input/output and image input; it can use an image-generation tool. That distinction matters: choosing Astra as the directing agent is a separate choice from the tool that renders pixels. [Official Astra model documentation](https://developers.openai.com/api/docs/models/gpt-6-astra).

**Recommendation, not a measured model advantage:** use Astra to plan and critique the sequence, inspect actual adjacent panels, compare candidates to the frozen brief, produce focused repair instructions, and maintain state/copy. Do not let it approve its own work through invented scores. Keep a separate reviewer and the owner’s complete-reader preference. Astra may improve those decisions, but this audit did not run a controlled model comparison proving that gain.

Before new raster work, have the directing setup replay the known P012/P017/P029/P037 contradictions, contextual P033 and strong counterexamples such as P018/P026/P044. It should identify the hard mismatches while recognizing successful contacts. Require evidence tied to the actual panels; false positives on good panels matter too. This small prospective calibration is not a new aesthetic scoring system. Use the same directing setup across A/B production routes so an art-tool comparison does not silently become a reasoning-model comparison.

## Tooling decision

Retain the current renderer for route A, but give it the correct storyboard rather than inherited wrong-event plates. Route B must add a real capability: controlled layout, separable character/background/effects assets and editable drawing corrections. A layer-capable raster/vector editor, and existing simple 3D blocking when geometry benefits, are appropriate roles; choosing a brand or installing another model is premature until the required correction is explicit. The current SVG/text approach remains useful if actual glyph containment, mouth attribution and face/contact clearance are reviewed.

If the same correctly directed renderer still cannot preserve contact, acting or identity after its bounded retry/correction, compare another renderer or staffed conventional drawing at that exact failure. Do not run several loosely related style prompts and call it a tooling comparison. Human-first production is the fallback only when real skilled capacity exists; agent output is not a substitute for the missing human benchmark.
